>[!info] MBR
>Master Boot Record

>GUID Partition Table

>Tzv. zavaděč je kód, který načte HW a spustí jádro OS

## Fyzický disk

>[!info]
Zařízení pro dlouhodobé ukládání dat

Skláda se komunikačního a napájecího rozhraní, controlleru a plotny nebo čipů pro ukládání dat

Typy podle konstrukce:

- **H**ard **D**rive **D**isk - HDD, tj. mechanický (obsahuje rotujicí plotnu)
- **S**olid **S**tate **D**rive - SSD, bez pohyblivých součástek

Typy podle rozhraní:

- Parallel ATA - Dnes se nepoužívá
- Serial ATA - V low-end zařízeních (max. 6Gbps)
- M.2 - Připojení přímo na MoBo, (gen 5 max. 112gbps)
- Serial Attached SCSI - SAS, hlavně v serverech (gen 4 max 24gbps)

## MBR a GPT

### MBR

- "oddílové schéma" - Partitioning scheme
	- Záznam v první sektoru disku (512-Byte)
- Obsahuje:
	- Bootloader
	- Partition table
	- Podpisy/ID disku
- Rozdělení disku na 512-Byte sektory, adresy uložené v 32-bit bloku = max. kapacita disku 2TB
- Max. 4 prim. oddíly, nebo 3. prim a rozšířený
- Neumí detekovat chyby

### GPT

- Bootloader v tzv. EFI oddílu
- Používá 64-bit adresový blok => kapacita disku 9,4 ZetaByte
- Až 128 oddílů
- Podporuje detekci chyb (CRC-32)
- Na konci disku je "recovery" oddíl se zálohou tabulky oddílů

## Nástroje

### `fdisk`

Interaktivní nástroj pro správu diskových oddílu.

Příkazy:

```bash
fdisk -l  # Vypíše všechny oddíly načtené systémem
fdisk /dev/<disk> # Spustí nástroj pro manipulaci s oddíly na daném disku
```

Při spuštění `fdisk` na disku můžeme pomocí klávesy `m` vypsat nápovědu.

Ta nám vypíše spoustu možností, nejdůležitější jsou následující:

- `n` - nový oddíl
- `d` - smazat oddíl
- `p` - vypíše oddíly na disku
- `w` - uloží změny a vypne nástroj
- `q` - vypne nástroj bez uložení změn

>[!info] `cfdisk`
>Alternativa pro `fdisk` je `cfdisk`, který je sofistikovanější ve smyslu UI, kde práce neprobíha čistě jenom pomocí příkazu, ale je zde interaktivní ovládání pomocí šipek

---

### `sfdisk`

Na rozdíl od `fdisk`, `sfdisk` není interaktivní, ale pro úpravu oddílu používá scripty.

---

>[!warning] Pozor
>`fdisk` ani `sfdisk` nepodporují GPT oddílový systém

---

### `parted`


Podporuje GPT oddílový systém

```bash
parted /dev/<disk>
```

Příkazy:

`mklabel` - nastaví oddílový systém
`mkpart` - vytvoří oddíl, nastavuje se zde typ oddílu, filesystem, začátek (min. 512B) a konec (max. velikost disku)

## Souborové systémy

>[!info] Definice
>Souborový systém, tj. file system (FS), je template pro ukládání dat na disku/svazku a ukládání jejich fyzické adresy na daném disku/svazku

>*Budou zmíněné pouze ty "hlavní" FS*
### XFS

- Nejčastěji je vidět jako file system pro disk s OS
- Tzv. žurnálový FS
	- změny souborů se ukládají do žurnálu (deníku), který periodicky tyto změny zapíše na disk.
	- Slouží k zachování integrity dat v případě neočekávané údalosti, např. výpadek
	- POZOR, XFS žurnáluje pouze metadata
- Používá 64-bit adresové záznamy

---

### EXT

- Extended File System
- Vytvořen přímo pro Linux

### EXT2

Podpora adresářu, odkazů, souborů pro zařázení (`/dev/sda`,...), práv (UGO)

### EXT3

Nově podpora žurnálování metadat i obsahu soborů a indexace souborů

### EXT4

- Podpora větších oddílů, souborů a počtů adresářů
- Timestamp s přesností na nanosekundy
	- Range: 14.12.1901 - 25.4.2514

---

### NTFS

- New Technology File System
- Ačkoliv je to primárně Windows FS, tak má podporu i v Linuxu
- Primární využití je pro přenost dat mezi platformami a není doporučen pro daily-use

## Práce s FS

### `lsblk`

Vypíše zařízení pro ukládání soubrou (disky, svazky,...), mountpointy, velikost, a jiné parametry

```bash
lsblk

# Vypíše i UUID a FS
lsblk -f
```

---

### `mkfs`

`mkfs` je příkaz který vytvoří na zvoleném oddílu FS (MaKe File System)

v základu je nastaven ext2, ale lze zvolit i spoustu jiných

```bash
# V základu EXT2
mkfs /dev/<oddíl nebo disk>

# Pokud chci jiný FS, tak pomocí tečky
mkfs.ext4 /dev/<oddíl nebo disk>
```

>[!warning] Důležité
>Pokud budu chtít pracovat s oddílem, tak na něm musím vytvořit FS

---

### `mount`/`umount`

`mount` slouží k připojení oddílu k systému pro účel operací s daty

```bash
mount /dev/<oddíl nebo disk> <složka kam připojit>
```

`umount` dělá přesně opačnou věc, kdy oddíl od systému odpojuje

```bash
umount /dev/<oddíl nebo disk>
```

---

### `dumpe2fs`

- Vypíše informace o super-blocku a všech blockových skupinách na disku
- Užitečný při debugovaní disku a jeho "zdravý"

```bash
dumpe2fs /dev/<zařizení s FS>
```

---

### `fsck`

Kontrola a oprava FS (do určité míry poškození)

```bash
fsck /dev/<zařizení s FS>
```

---

### `badblocks`

Vyhledá vadné blocky na disku

```bash
badblocks /dev/<zařízení s FS>
```

---

### `tune2fs`

- Umožňuje měnit parametry FS
- Parametry lze vypsat pomocí `dumpe2fs` nebo `tune2fs -l`

```bash
tune2fs /dev/<zařízení s FS>
```

>[!danger] Na vlastní nebezpečí
>Může teoreticky poškodit FS, víc informací v `man tune2fs`

---

### `df`

Vypíše údaje u využití disku

```bash
df /dev/<zařízení s FS>
```

---

### `debugfs`

Debugger pro ext2/3/4

```bash
debugfs
```

## `/etc/fstab`

Tento soubor slouží pro automatické připojení disku k systému při bootu

Syntaxe v něm je následující

```bash
<svazek>  <mount point>  <FS>  <mount options>  <zálohy> <kontrola integrity>

# Př svazek md1 připojen do složky /mnt s defaultním nastavením,
# automatickým FS, bez záloh a kontroly integrity
/dev/md1  /mnt  auto  defaults  0 0

# připojení pomocí UUID a nastavením uživatelských kvót
UUID=... /backups  ext4  defaults,usrquota  0 0
```

>[!danger] POZOR
>svazky jako `/dev/md1` mají občas chuť se přejmenovat na `/dev/md127`, proto doporučuji používat UUID, jinak se může stát, že `fstab` svazek při bootu nenajde a dá se do emergency módu
