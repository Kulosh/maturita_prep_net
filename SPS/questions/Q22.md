# Diskové pole RAID v systému Linux

## Definice

>[!info] Diskové pole
>Uložiště poskládané z více disků

>[!info] RAID
>Redundant array of independent disks - Redundantní pole nezávislých disků
>Diskové pole složené z více disků s účelem udržet integritu dat při výpadku disku v diskovém poli
>Používá se v prostředí, kde jsou data důležita a nechceš o ně přijít (datacentra,...)

---

## Úrovně RAID

### RAID 0 (Stripping)

Funguje tak, že veme vstupní data a po rovnoměrných dílech rozdělí data mezi dva disky na půl.

Složen min. z 2 disků, kapacita disků se sčítá následovně

$$
\text{$kapacita$ $nejmenšího$ $disku$ * $počet$ $disků$ = $celková$ $kapacita$ $svazku$} 
$$

RAID 0 není ve své podstatě RAID, protože při výpadku jednoho disku dochází ke ztrátě poloviny dat, resp. ztrátě všech (hodně štěstí s obnovou když máš půlku dat) = **neplní redundanci**

![RAID saving scheme](/SPS/imgs/Q22/raid0.png)

---

### RAID 1 (Mirroring)

Vstupní data jsou zapsána na 2 disky (2 disky se stejnými daty)

Jsou potřeba 2 disky, pokud mají rozdílnou kapacitu tak výsledný svazek bude mít kapacitu toho menšího ze 2 disků

Při výpadku jednoho disku jsou data zachována na druhém

Teoreticky 2x větší rychlost čtení

![RAID saving scheme](/SPS/imgs/Q22/raid1.png)

---

### RAID 5 (Stripping with parity)

RAID 0 na steroidech

Skládá se z 3+ disků, výpočet velikost:

$$
\text{$nejmenší$ $disk$ * $počet$ $disků$ - $nejmenší$ $disk$ = $celková$ $kapacita$ $svazku$} 
$$

Data jsou rozdělená podobně jako v RAID 0 na více disků, ale jeden disk slouží jako paritní => v případě výpadku jednoho disku je paritní schopen dopočítat ztracená data

Rychlejší čtení

![RAID saving scheme](/SPS/imgs/Q22/raid5.png)

---

### RAID 6 (Stripping with double parity)

Stejný jako RAID 5 ale místo jedné parity jsou dvě - potřeba minimálně 4 disky

## `mdadm`

Příkaz slouží k vytváření diskových polí

### RAID 0

*Pracujeme zde s disky `/dev/sdb`, `/dev/sdc` a `/dev/sdd`*

```bash
mdadm  --create /dev/md0 --level=0 --raid-devices=3 /dev/sd[b-d]
echo 'DEVICES /dev/sd[b-d]' > /etc/mdadm.conf
mdadm --detail --scan >> /etc/mdadm.conf
mkfs.ext4 /dev/md0
mount /dev/md0 #kam#
```

---

### RAID 1

*Pracujeme zde s disky `/dev/sdb` a `/dev/sdc`*

```bash
mdadm  --create /dev/md1 --level=1 --raid-devices=2 /dev/sd[bc]
echo 'DEVICES /dev/sd[bc]' > /etc/mdadm.conf
mdadm --detail --scan >> /etc/mdadm.conf
mkfs.ext4 /dev/md1
mount /dev/md1 #kam#
```

---

### RAID 5

*Pracujeme zde s disky `/dev/sdb`, `/dev/sdc` a `/dev/sdd`*

```bash
mdadm  --create /dev/md5 --level=5 --raid-devices=3 /dev/sd[b-d]
echo 'DEVICES /dev/sd[b-d]' > /etc/mdadm.conf
mdadm --detail --scan >> /etc/mdadm.conf
mkfs.ext4 /dev/md5
mount /dev/md5 #kam#
```

---

### RAID 6

*Pracujeme zde s disky `/dev/sdb`, `/dev/sdc`, `/dev/sdd` a `/dev/sde`*

```bash
mdadm  --create /dev/md6 --level=6 --raid-devices=4 /dev/sd[b-e]
echo 'DEVICES /dev/sd[b-e]' > /etc/mdadm.conf
mdadm --detail --scan >> /etc/mdadm.conf
mkfs.ext4 /dev/md6
mount /dev/md6 #kam#
```

### Rozšíření svazku

#### Spare

Pro rozšíření svazku použijeme příkaz `mdadm --add`, který přidá disk jako takzvaný `spare`, to znamená, že pokud vypadne jeden disk v poli, tento `spare` disk ho hned nahradí a začne dopočítávat data.

*Syntax:*

```bash
mdadm /dev/md1 --add /dev/sdd
```

pomocí tohoto příkazu jsme přidali disk `/dev/sdd` do pole `/dev/md1` jako `spare` 

---

#### Active

Pokud chceš přidat disk jako active a zvětšit kapacitu pole použij následující příkaz:

*Scénář - RAID 5 se 3 disky, chci přidat čtvrtý*

```bash
mdadm --grow /dev/md5 --raid-devices=4 --add /dev/sde
```

Úspěšně jsme přidali čtvrtý disk, ale **POZOR**, velikost filesystému, tedy reálně použitelného místa zůstala stejná.

*Původně 3x 1GB disk, teď 4x 1GB disk*
*3x 1GB = 2GB kapacita, chceme zvětšit na 3GB kapacitu*

---

#### `resize2fs`

Příkaz pro rozšíření filesystému

*Syntax:*
*(Případ s RAID 5)*

```bash
resize2fs /dev/md5
```

## `fstab`

Pokud chceme, aby se svazek, nebo disk, automaticky připojovali při bootu, tak ho musíme přidat do souboru `/etc/fstab`.

Tento soubor v sobě drží následující informace

- jaký disk/svazek (co) (`UUID` (spolehlivější) nebo cesta `/dev/...`)
- do jaké složky ho připojit (kam)
- jaký má filesystem
- možnosti připojení (`defaults`, `ro` (read-only), `rw` (read-write),...)
- zálohování (defaultně `0`)
- pořadí kontroly disku při bootu (defaultně `0`)

Pro jednoduché vložení UUID do `fstab` bez zdlouhavého opisování můžeme použít jednoduché přesměrování v kombinaci s `grep`. Na toto nám stačí znát cestu k zařízení ve formátu `/dev/<svazek nebo zařízení>`

*Příklad pro `/dev/md5`, který je připojen v `/raid`*

```bash
lsblk -f | grep /dev/md5 >> /etc/fstab
```

(Tento příkaz přidá kromě `UUID` také filesystem a spoustu dalších věcí které nejsou potřeba)

`fstab` budé následně vypadat takhle (`UUID` se budou lišit)

```bash
...
UUID=8eaa8e19-950a-4298-8796-d8beb684dd90 /boot xfs defaults 0 0
md5  ext4  1.0  7c48f544-0a42-4af1-be2b-1b63a3157170 1G  0%  /raid
```

Pro náš účel přepíšeme poslední řádek na následující formát

```bash
...
UUID=8eaa8e19-950a-4298-8796-d8beb684dd90 /boot xfs defaults 0 0
UUID=7c48f544-0a42-4af1-be2b-1b63a3157170 /raid ext4 defaults 0 0
```

V tento moment se disk/svazek s tímto `UUID` při boot připojí do složky `/raid`
